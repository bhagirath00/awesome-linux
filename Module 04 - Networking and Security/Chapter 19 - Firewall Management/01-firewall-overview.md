# Linux Firewall Architecture: The Netfilter Subsystem, Conntrack, and Frontends

## Overview

A firewall is the primary defensive perimeter of a Linux operating system. It inspects incoming, outgoing, and forwarded network packets against security policies, deciding whether each packet should be allowed (**`ACCEPT`**), silently discarded (**`DROP`**), or actively rejected with an error (**`REJECT`**).

In Linux, firewalls are not separate third-party software programs. Packet filtering is built directly into the kernel via the **Netfilter** framework.

This lesson explores the kernel Netfilter hooks, the `conntrack` state engine, and the relationship between low-level tools (`iptables`, `nftables`) and high-level management frontends (**`ufw`** on Ubuntu and **`firewalld`** on RHEL).

---

## 1. The Kernel Netfilter Architecture & The 5 Hook Points

As network packets traverse the Linux kernel network stack, they trigger five distinct **Netfilter Hook Points**:

```text
Incoming Packet
       │
       ▼
[ 1. PREROUTING ] ──> (Destination NAT / Port Forwarding happens here)
       │
       ├─────────────────── Routing Decision ───────────────────┐
       │ (Packet is for local machine)                           │ (Packet is for another host)
       ▼                                                         ▼
[ 2. INPUT ]                                              [ 3. FORWARD ]
       │ (Local firewall rules)                                  │ (Docker / Router forwarding)
       ▼                                                         │
Local Process (e.g. Nginx, SSH)                                  │
       │                                                         │
       ▼ (Outgoing packet created locally)                       │
[ 4. OUTPUT ]                                                    │
       │                                                         │
       └─────────────────── Routing Decision ───────────────────┘
                                   │
                                   ▼
                            [ 5. POSTROUTING ] ──> (Source NAT / Masquerading happens here)
                                   │
                                   ▼
                            Outgoing Packet
```

### The 5 Hook Responsibilities:
1. **`PREROUTING`**: Triggered immediately upon packet arrival before any routing decisions are made (used for DNAT / Port Forwarding).
2. **`INPUT`**: Triggered if the packet is destined for a local socket on this machine.
3. **`FORWARD`**: Triggered if the packet is addressed to a different machine (e.g., Docker container routing, Kubernetes pod routing).
4. **`OUTPUT`**: Triggered by packets generated by local processes on this machine.
5. **`POSTROUTING`**: Triggered immediately before packets leave the network interface (used for SNAT / Masquerading).

## 2. Stateful Filtering: The Connection Tracker (`conntrack`)

Modern Linux firewalls are **Stateful**. The kernel does not treat each packet as an isolated event; it tracks the state of every TCP, UDP, and ICMP connection in memory via the **`conntrack`** subsystem.

Every packet is classified into one of four fundamental connection states:

| Connection State | Meaning & Operational Significance |
| :--- | :--- |
| **`NEW`** | The packet is attempting to initiate a brand-new connection (e.g., an incoming TCP SYN packet). |
| **`ESTABLISHED`** | The packet belongs to an existing, verified bidirectional connection that has already been approved. |
| **`RELATED`** | The packet is initiating a secondary connection associated with an existing connection (e.g., FTP data channels or ICMP error messages). |
| **`INVALID`** | The packet does not conform to known protocols, is corrupted, or has illegal flag combinations. **(Always dropped!)** |

## 3. The Defense-in-Depth Principle: Default DROP

In enterprise security (CIS Benchmarks), the fundamental security posture is **Default DROP**:

```text
1. Default Policy on INPUT   ──> DROP (Block EVERYTHING by default!)
2. Allow Loopback Traffic    ──> ACCEPT on 'lo' (Local IPC must work)
3. Allow Active Connections  ──> ACCEPT if state is ESTABLISHED,RELATED
4. Whitelist Specific Ports  ──> ACCEPT on Port 22 (SSH), Port 443 (HTTPS)
```

By allowing `ESTABLISHED,RELATED` traffic, when your server makes an outbound request (such as downloading a package via `apt update`), the return packets from the repository are automatically recognized and permitted back into the server!

## 4. The Evolution of Linux Firewall Frontends

Over the decades, Linux has provided multiple management interfaces over Netfilter:

```text
[ High-Level Friendly Frontends ]   UFW (Ubuntu / Debian)     Firewalld (RHEL / Rocky / Fedora)
                                                   │                       │
[ Unified Modern Kernel Engine  ]                  └───────────┬───────────┘
                                                               ▼
                                                           nftables (Modern standard)
                                                               │ (Legacy: iptables)
                                                               ▼
[ Linux Kernel Core             ]                      Netfilter Subsystem
```

- **`iptables`** *(Legacy)*: The traditional CLI utility. Direct, low-level, but complex syntax.
- **`nftables`** *(Modern Core)*: The modern unified successor replacing `iptables`, `ip6tables`, and `ebtables` with faster rule evaluation.
- **`ufw` (Uncomplicated Firewall)**: Canonical's user-friendly CLI frontend for Ubuntu/Debian.
- **`firewalld`**: Red Hat's dynamic, zone-based firewall daemon with D-Bus support.

---

## Summary

- Linux firewalling is built directly into the kernel via the **Netfilter** framework.
- Packets traverse five hook points: `PREROUTING`, `INPUT`, `FORWARD`, `OUTPUT`, `POSTROUTING`.
- Stateful firewalls rely on `conntrack` to identify `ESTABLISHED` and `RELATED` connections.
- The standard production baseline is **Default DROP**: deny all incoming traffic except whitelisted service ports and established reply packets.
- `ufw` is the standard on Ubuntu/Debian; `firewalld` is the standard on RHEL/Rocky.
