# Chapter 42: Disk Performance - Storage I/O Monitoring and iotop

## 1. Introduction: Identifying Disk Bottlenecks

Storage I/O is frequently the slowest subsystem in the entire computing architecture. A CPU operates in nanoseconds, RAM in tens of nanoseconds, but mechanical disks operate in milliseconds and solid-state drives in hundreds of microseconds.

When an application runs slowly, engineers often examine CPU metrics first. However, if the CPU is spending 40% of its time stalled waiting for block I/O (`%wa` or `iowait` in `top`), the storage subsystem is the bottleneck.

```
+--------------------------------------------------------------------------+
|                     Storage Performance Triage Flow                      |
+--------------------------------------------------------------------------+
|  1. High Load Average + High %wa in top?                                 |
|     =====> Investigate Storage Saturation                                |
|                                |                                         |
|  2. Which physical disk or partition is struggling?                      |
|     =====> Run: iostat -xz 1                                             |
|     Look for: High r_await/w_await (>10ms) and %util (>85%)              |
|                                |                                         |
|  3. Which specific Process ID is doing the heavy reads/writes?           |
|     =====> Run: sudo iotop -o                                            |
|     Isolate the exact PID generating IOPS!                               |
+--------------------------------------------------------------------------+
```

## 2. Real-Time Process I/O Monitoring with `iotop`

While `iostat` shows which physical disk partition is busy, **`iotop`** tells you **which exact process or thread is generating the I/O**.

Like `top`, `iotop` displays a real-time interactive terminal dashboard, but sorted by disk read/write bandwidth:

```bash
# Install iotop
sudo apt install -y iotop   # Ubuntu/Debian
sudo dnf install -y iotop   # RHEL/Rocky

# Run iotop showing ONLY processes actively doing I/O (-o)
sudo iotop -o
```

```
Total DISK READ: 42.15 M/s | Total DISK WRITE: 12.40 K/s
Current DISK READ: 44.80 M/s | Current DISK WRITE: 8.50 K/s
  TID  PRIO  USER     DISK READ  DISK WRITE  SWAPIN      IO>    COMMAND
14205 be/4 devops    41.80 M/s    0.00 B/s  0.00 %  94.20 % node /opt/etl/extract.js
  890 be/4 postgres   0.00 B/s   12.40 K/s  0.00 %   0.50 % postgres: writer
```

### Key Columns Explained:
- **`DISK READ` / `DISK WRITE`**: Real-time I/O throughput generated by this process.
- **`SWAPIN`**: Percentage of time the process spent stalled waiting for swapped memory pages to be read back from disk into RAM.
- **`IO>`**: **The primary metric**. Percentage of time the process was blocked waiting for I/O. A value of `94.20%` means this process is almost completely stalled waiting for disk blocks!

### Batch Mode for Logging:
Capture 3 snapshots of active I/O consumers in non-interactive scripts:
```bash
sudo iotop -b -o -n 3
```

## 3. Per-Process I/O Auditing with `pidstat -d`

The `pidstat` utility from `sysstat` provides historical I/O counters per process without launching a full-screen curses UI:

```bash
pidstat -d 1 3
```

```
11:20:00 AM   UID       PID   kB_rd/s   kB_wr/s kB_ccwr/s iodelay  Command
11:20:01 AM  1000     14205  42800.00      0.00      0.00      85  node
11:20:01 AM   105       890      0.00    240.00     45.00       2  postgres
```
- `kB_rd/s`: Kilobytes read per second.
- `kB_wr/s`: Kilobytes written per second.
- `iodelay`: Clock ticks spent waiting for synchronous disk I/O.

## 4. Benchmarking Raw Storage Throughput with `fio`

Never guess disk capability; measure it using **`fio`** (Flexible I/O Tester), the industry-standard storage benchmarking tool:

```bash
# Install fio
sudo apt install -y fio

# Benchmark 4K Random Read IOPS (Direct I/O, bypassing RAM page cache)
fio --name=random-read-test \
    --ioengine=libaio \
    --direct=1 \
    --rw=randread \
    --bs=4k \
    --size=1G \
    --numjobs=4 \
    --runtime=30 \
    --group_reporting \
    --filename=/data/test.fio
```
This test reveals your drive's true raw hardware IOPS and P99 latency.

---

## 5. Summary Takeaways

- High `%wa` (I/O wait) in `top` indicates that CPU cores are idling while waiting for disk operations.
- Cross-reference with `iostat -xz 1` to locate the saturated disk device.
- Use `sudo iotop -o` to identify the rogue PID saturating the disk bandwidth.
- Use `pidstat -d 1` for lightweight, non-interactive per-process I/O tracking.
- Benchmark real storage performance using `fio`.
